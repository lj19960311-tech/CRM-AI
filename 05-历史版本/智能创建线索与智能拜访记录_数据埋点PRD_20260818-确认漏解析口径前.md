# 智能创建线索与智能拜访记录数据埋点 PRD

> 版本：V1.0  
> 状态：评审稿  
> 日期：2026-08-18  
> 范围：智能创建线索、智能拜访记录

## 0. 重要口径说明

用户指定的计算口径为：

> 准确率 = 编辑数量 ÷ 创建成功数量 × 100%

该指标数值越高，代表人工修改越多，实际含义更接近“编辑率”。为避免误读，本 PRD 保留上述项目口径，并要求埋点指标同时提供：

> 免编辑率 = 1 − 准确率

## 1. 背景与目标

智能创建线索通过语音录入、结构化解析、确认并提交完成线索创建；智能拜访记录采用同类智能生成与人工确认流程。需要建立统一的数据埋点，衡量入口使用、创建转化、人工编辑及各字段的修改情况。

### 1.1 目标

- 统计各入口和按钮的点击次数、点击人数。
- 统计创建或提交成功的数量、人数及成功率。
- 统计发生编辑的记录数量、编辑人数及项目约定的准确率。
- 统计每个字段的编辑数量、编辑人数、字段准确率和字段免编辑率。
- 支持按业务场景、端、入口、业务板块、产品类型和日期等维度拆分。

## 2. 核心指标口径

| 指标 | 定义/公式 | 去重及说明 |
|---|---|---|
| 按钮点击次数 | 目标按钮点击事件总次数 | 同一用户重复点击累计 |
| 按钮点击人数 | 触发目标按钮点击事件的 `user_id` 去重数 | 按统计周期去重 |
| 创建成功数量 | `create_success` 或 `submit_success` 对应的业务记录数 | 按 `record_id` 去重，重试仅计一次 |
| 创建成功人数 | 成功事件的 `user_id` 去重数 | 按统计周期去重 |
| 成功率（次数） | 创建成功数量 ÷ 提交点击次数 × 100% | 使用同一 `attempt_id` 关联分子、分母 |
| 成功率（人数） | 创建成功人数 ÷ 提交点击人数 × 100% | 按同一场景、同一统计周期计算 |
| 编辑数量 | 创建成功记录中，至少一个字段最终值与 AI 初始值不同的 `record_id` 数 | 一条记录编辑多个字段仍只计一条 |
| 编辑人数 | 至少产生一条编辑记录的 `user_id` 去重数 | 按统计周期去重 |
| 准确率（项目口径） | 编辑数量 ÷ 创建成功数量 × 100% | 越高表示人工修改越多 |
| 免编辑率 | （创建成功数量 − 编辑数量）÷ 创建成功数量 × 100% | 等于 1 − 项目口径准确率 |
| 字段编辑数量 | 成功记录中，该字段最终值与 AI 初始值不同的 `record_id` 数 | 同一记录同一字段多次修改只计一次 |
| 字段编辑人数 | 编辑过该字段的 `user_id` 去重数 | 按字段、统计周期去重 |
| 字段准确率 | 字段编辑数量 ÷ 该字段适用的创建成功记录数 × 100% | 越高表示该字段修改越多 |
| 字段免编辑率 | 1 − 字段准确率 | 建议作为模型表现的主展示指标 |

### 2.1 字段“发生编辑”的判定

- 比较结构化解析或智能生成完成时的字段快照 `ai_original_value` 与最终提交成功时的字段值 `final_value`。
- 比较前进行标准化：去除首尾空格、统一全角/半角；电话仅去除空格和连接符；枚举字段按 `option_id` 比较，不按展示文案比较。
- AI 初始值为空、用户补全为非空，计为编辑。
- AI 初始值非空、用户清空，计为编辑。
- 用户修改后又改回 AI 初始值，最终不计字段编辑；过程编辑次数仍通过 `field_edit` 事件统计。
- 条件字段的分母仅包含该字段在成功记录中适用且展示的记录；未展示的记录不进入分母。
- 公司名称支持用户编辑，按 AI 初始值与最终提交值的标准化比较结果判定是否发生编辑。

## 3. 埋点事件设计

### 3.1 公共参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `event_id` | string | 是 | 事件唯一标识，用于去重 |
| `event_time` | datetime | 是 | 客户端事件时间，ISO 8601 |
| `user_id` | string | 是 | 登录用户唯一标识，禁止上报姓名和手机号 |
| `session_id` | string | 是 | 单次访问会话标识 |
| `attempt_id` | string | 是 | 一次智能创建或提交尝试标识，贯穿整条漏斗 |
| `scene` | enum | 是 | `voice_lead` / `smart_visit` |
| `platform` | enum | 是 | `mini_program` / `pc` / 其他实际端 |
| `page_name` | string | 是 | 事件发生页面 |
| `entry_source` | string | 否 | 首页、列表页、详情页等实际入口 |
| `business_line_id` | string | 否 | 业务板块 ID |
| `product_type_id` | string | 否 | 末级产品类型 ID |
| `app_version` | string | 是 | 应用版本 |
| `trace_id` | string | 否 | 前后端链路追踪 ID |
| `is_test_user` | boolean | 是 | 是否测试、自动化或压测账号 |

### 3.2 事件清单

| 事件名 | 触发时机 | 关键参数 | 适用场景 |
|---|---|---|---|
| `smart_entry_click` | 点击智能创建入口 | `button_name`, `entry_source` | 两者 |
| `record_start_click` | 点击开始录音 | `record_round` | 语音线索；拜访如有录音则复用 |
| `record_stop_click` | 点击停止录音 | `record_round`, `duration_ms` | 同上 |
| `rerecord_click` | 点击重新录音 | `record_round`, `text_length` | 同上 |
| `parse_submit_click` | 点击下一步或智能生成 | `button_name` | 两者 |
| `parse_result` | 解析请求结束 | `result`, `error_code`, `latency_ms`, `field_snapshot_id` | 两者 |
| `confirm_page_view` | 成功进入确认或编辑页 | `record_temp_id`, `field_count` | 两者 |
| `field_edit` | 字段发生一次用户修改并失焦或确认 | `field_code`, `edit_seq`, `original_empty`, `edit_method` | 两者 |
| `submit_click` | 点击创建或提交按钮 | `button_name`, `validation_result` | 两者 |
| `submit_result` | 后端返回最终结果 | `result`, `record_id`, `error_code`, `edited_field_count` | 两者 |

### 3.3 服务端统计要求

- `submit_result` 必须以后端业务成功为准。
- 客户端收到成功提示但后端未生成 `record_id`，不得记为成功。
- `record_id`、`attempt_id`、`user_id` 必须可关联。
- 禁止在埋点中上报联系人姓名、电话、录音文本、识别全文或完整需求文本。
- 字段值比较在业务后端完成，埋点仅上报字段是否发生编辑及编辑字段数量。

### 3.4 事件参数补充

| 参数 | 取值/说明 |
|---|---|
| `result` | `success` / `fail` |
| `error_code` | 统一错误码；成功时为空。错误文案单独维护映射，避免高基数 |
| `field_snapshot_id` | 解析结果快照 ID，用于后端获取 AI 初始字段值，不在埋点中上传原文 |
| `field_code` | 稳定字段编码，不使用可能变化的中文展示名 |
| `edit_seq` | 同一 `attempt_id + field_code` 下从 1 递增，用于统计过程编辑次数 |
| `edit_method` | `typing` / `select` / `clear` / `autofill` / `other` |
| `edited_field_count` | 最终提交时被判定为编辑的字段数 |
| `validation_result` | `pass` / `fail`；失败时附 `validation_error_code` |

## 4. 字段级统计要求

### 4.1 语音创建线索字段

| field_code | 字段名称 | 适用分母 | 备注 |
|---|---|---|---|
| `company_name` | 公司名称 | 该字段展示的成功记录 | 支持用户编辑；按标准化后的企业标识或文本比较 |
| `business_product` | 业务板块-产品类型 | 字段适用的成功记录 | 按末级 `option_id` 比较 |
| `detail_requirement` | 详细需求 | 字段适用的成功记录 | 文本标准化后比较 |
| `lead_source` | 线索来源 | 字段适用的成功记录 | 按 `option_id` 比较 |
| `contact_name` | 客户联系人姓名 | 字段适用的成功记录 | 只上报是否变化，不上报字段值 |
| `contact_phone` | 客户联系人电话 | 字段适用的成功记录 | 只上报是否变化，不上报字段值 |

### 4.2 智能拜访记录字段

以下 9 个字段均纳入字段编辑数量、字段编辑人数、字段准确率和字段免编辑率统计。`field_code` 为本 PRD 建议编码；字段类型、是否必填及具体格式仍需结合智能拜访记录原需求确认。

| field_code（建议） | 字段名称 | 建议类型 | 编辑判定 |
|---|---|---|---|
| `company_name` | 企业名称 | 文本/企业选择 | 比较标准化后的企业标识或文本；最终方式待确认 |
| `visit_time` | 拜访时间 | 日期时间 | 比较统一时区和格式后的时间值 |
| `customer_name` | 拜访客户姓名 | 文本 | 比较标准化后的文本，不上报字段原值 |
| `customer_position` | 拜访人职务 | 文本 | 比较标准化后的文本，不上报字段原值 |
| `next_visit_time` | 下次拜访时间 | 日期时间 | 比较统一时区和格式后的时间值 |
| `is_key_project` | 是否是重点项目 | 布尔/枚举 | 按稳定的布尔值或枚举 ID 比较 |
| `visit_location` | 拜访位置 | 位置/文本 | 比较标准化后的位置标识或文本；最终方式待确认 |
| `visit_content` | 拜访内容 | 多行文本 | 比较标准化后的文本，不上报字段原值 |
| `follow_up_items` | 需跟进事项 | 多行文本 | 比较标准化后的文本，不上报字段原值 |

统计公式和事件复用本 PRD，不新增另一套口径。上述字段在成功提交记录中适用且展示时进入字段准确率分母；AI 未解析、用户补全的字段计为编辑。

## 5. 数据处理规则

- 统计时区统一为 `Asia/Shanghai`，自然日为 00:00:00—23:59:59。
- 次数类成功分子按 `record_id` 去重，人数按 `user_id` 去重。
- 同一 `attempt_id` 多次点击提交：点击次数如实累计，成功记录仅按 `record_id` 计一次。
- 跨端继续操作时 `attempt_id` 应保持一致；无法保持时记录 `source_attempt_id`。
- 埋点重复上报按 `event_id` 去重。
- 迟到数据允许 T+1 回补，数据产出需记录最近更新时间。
- 测试账号、自动化账号和内部压测流量通过 `is_test_user` 或环境字段排除。
- 禁止上报语音音频、识别全文、联系人姓名、手机号和详细需求全文。

## 6. 验收标准

| 验收项 | 通过标准 |
|---|---|
| 链路完整 | 每个成功 `record_id` 可关联唯一的 `scene`、`attempt_id`、`user_id`、`parse_result` 和 `submit_result` |
| 数量准确 | 抽取测试样本逐条核对，按钮次数、成功记录数、编辑记录数与业务日志一致 |
| 人数准确 | 同一用户重复操作在指定周期内只计 1 人，跨周期可分别计入 |
| 字段判定 | 覆盖空→非空、非空→空、修改后改回、枚举展示名变化、条件字段未展示等案例 |
| 公式一致 | 埋点明细与离线 SQL 计算的成功率、项目口径准确率、免编辑率结果一致 |
| 隐私合规 | 事件明细中不存在音频、识别原文、联系人姓名、手机号和详细需求全文 |
| 失败可诊断 | 解析失败和提交失败均能按 `error_code` 聚合，且错误码不包含个人信息 |

## 附录 A：指标计算示例

示例：提交点击 120 次、100 人；创建成功 90 条、80 人；36 条记录、30 人发生编辑。

| 指标 | 结果 |
|---|---:|
| 成功率（次数） | 90 ÷ 120 = 75% |
| 成功率（人数） | 80 ÷ 100 = 80% |
| 准确率（项目口径） | 36 ÷ 90 = 40% |
| 免编辑率 | （90 − 36）÷ 90 = 60% |
